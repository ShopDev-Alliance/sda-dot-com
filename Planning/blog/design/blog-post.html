Building a Metaobject-Powered Blog on Shopify (Without Hating Yourself)

Shopify blogs get a bad rap for a reason — but with a little Liquid, a sprinkle of metaobjects, and the right reading UX, you can ship something that feels like it belongs on vercel.com/blog.

MR Maya Rossi
Senior Shopify Engineer · SDA #072 April 14, 2026 8 min read 0% read

If you've ever tried to build a technical blog on Shopify, you know the feeling. You open the rich text editor, paste in a code block, and watch your <div> turn into HTML entities. The image has a mystery <p> wrapper. There's no table of contents. And don't even think about a reading progress bar.

This post is about how we fixed all of that at ShopDev Alliance — without leaving Shopify, without a headless rebuild, and without giving up the editor-friendliness that keeps the marketing team from sending us angry Slack messages at 11pm.

The problem with Shopify blogs#

Out of the box, a Shopify article is a single article.content rich-text blob. That's fine for a press release. It's not fine for anything with structure — tutorials, engineering posts, interviews, changelogs. You end up fighting TinyMCE to do things like:

  • Render a code block with a language label, line numbers, and copy button
  • Add callouts (note / warning / tip) inline between paragraphs
  • Insert a product card, embedded tweet, or diagram
  • Generate a table of contents that automatically stays in sync
i

Heads up

This guide assumes you're on Online Store 2.0 with access to metaobjects. If you're still on a 1.0 theme, the Liquid is similar — you'll just swap metaobjects for custom app-data JSON.

Modeling posts with metaobjects#

Instead of relying on article.content as one giant blob, we model each post as a sequence of typed blocks. Metaobjects are perfect for this — they give you structured data with references, and the theme editor picks them up for free.

Linking blocks to articles

Each article gets a metafield called custom.blocks with type list.metaobject_reference. Authors drag blocks in, reorder them, and the theme renders them in sequence. No more wrestling with the rich text editor.

Reading UX that respects your readers#

A great blog post earns attention — but a great blog makes attention comfortable. These are the UX affordances we consider table-stakes on every post we ship:

  1. Reading progress bar — pin a thin bar to the top that fills as the reader scrolls the article.
  2. Sticky table of contents with active-section highlighting using IntersectionObserver.
  3. Copy-link on every heading — hover reveals a # anchor that copies a URL to the clipboard.
  4. Copy-to-clipboard on code blocks, with a confirmed state.
  5. Generous line-height (1.6–1.75) and a readable measure (60–75 characters).

A note on performance#

Metaobject rendering is server-side — the theme fetches references during Liquid evaluation, so the first paint is already complete HTML. The only client JS we ship for the post template is ~3kb for progress, TOC, and copy buttons. Everything else (syntax highlighter, comments, reactions) is lazy-loaded when it enters the viewport.

We also precompute read-time on publish and store it as a metafield — no runtime word-counting.

Takeaways#

  • Shopify's blog is only as limited as the data model you give it. Use metaobjects to structure posts into typed blocks.
  • Keep snippets tiny and focused — one per block kind. Let Liquid's case be your router.
  • Invest in reading UX: progress bar, sticky TOC, copy-anchors, copy-code. None of it is expensive; all of it is noticed.
  • Ship ~3kb of post-template JS. Anything more and you're punishing your readers for your feature choices.

If you want the full code, it's open-source on our GitHub, and we demo this exact setup in the #theme-building channel in Slack every other Friday. Come say hi.
